# CUDA 精确三角形计数研究计划书

## 一 研究定位与目标

本项目对应《并行计算》课程 P09 单 GPU 上的精确三角形计数。拟以“基于任务规模分级的 GPU 精确三角形计数”为课程论文题目，研究不同规模的邻接表交集任务如何映射到 CUDA 线程与 warp。英文工作题目为 Workload Aware GPU Triangle Counting with Thread and Warp Scheduling。最终题目依据实现和实验结果调整。

研究对象是静态无向简单图。输入经统一清洗后，输出全图三角形总数；计数必须与独立参考完全一致。项目同时提交代码、实验原始记录、复现说明和课程论文。当前阶段为立项，尚无 GPU 实测结果。

课程要求是自行实现 CUDA 计数与任务分配，完成基础版、改进版、正确性验证和性能分析。排序与归约可调用 CUB 或 Thrust。完整图算法库可以作为外部参考，不能替代自己的计数核心。

主要研究问题如下。

- RQ1 同一交集算法下，一线程一边与一 warp 一边的性能分界如何随任务规模变化？
- RQ2 基于定向后邻接表长度的分级调度，能否在不同图结构上降低计数耗时？
- RQ3 加上任务分类、传输和图预处理后，优化是否仍然有效？重复计数多少次才能摊销准备成本？

预期产出是可复现实现、明确的适用条件及失败案例分析。线程与 warp 分级本身属于已有优化思路，不预先宣称算法首创。课程论文可围绕设计和系统实验形成贡献；若面向学术投稿，还需扩展相关工作、验证差异与新增贡献。

完成标准为所有验证案例精确通过、至少三张真实图与多类合成图完成同硬件比较、原始计时可追溯、论文中的每项性能结论有数据支撑。不设未经实验的加速倍数承诺。

## 二 问题定义与正确性依据

输入 G=(V,E)，无自环、无重复无向边。三角形为三个不同顶点的无序集合，且三个无序点对均属于 E。读取有向数据时，只要任一方向存在边，就保留对应无向边。该规则对所有实现一致。

预处理先去自环，再把边规范为 (min(u,v),max(u,v)) 并去重。原始编号映射为连续编号，保留映射表或其校验摘要；显式给出的孤立顶点保留。计算清洗后无向度数 d(u)，按 (d(u),u) 的字典序建立全序，边从较小者指向较大者。

设 F(u) 为向前邻居集合，E+ 为定向边集合，则总数为 T = Σ_(u,v)∈E+ |F(u)∩F(v)|。每张向前邻接表按统一的连续顶点编号排序，方便归并与二分查找；定向所用全序与列表排序键可以不同，但实现必须保持一致约定。

正确性证明：对任意三角形，按定向全序记其顶点为 a≺b≺c。c 同时属于 F(a) 与 F(b)，所以边 a→b 发现一次。边 a→c 和 b→c 无法通过更靠后的第三个顶点再次发现同一三角形。反过来，每个交集元素都对应三条存在的边。因此既不遗漏也不重复。

数据结构采用向前 CSR：offset 保存各顶点邻接段的起止偏移，neighbors 连续存储向前邻居。顶点编号计划使用 uint32，偏移和计数使用 uint64；读取、求和及类型转换要检查溢出。若图规模不满足编号范围则明确拒绝或扩展类型。

计数核心选用短表遍历与长表二分。令 a=min(|F(u)|,|F(v)|)，b=max(|F(u)|,|F(v)|)，粗略工作量代理为 w=a·ceil(log2(b+1))；a=0 时直接跳过。该代理仅估计工作量，不等于 GPU 实际运行时间。总复杂度可按各边二分工作量之和描述。

## 三 并行算法与实现方案

统一流程为读取和清洗、度数定向、构建排序 CSR、生成边任务、任务分类、传输、CUDA 计数、归约与结果输出。各版本共享同一图语义和主要存储格式，减少无关因素。

| 版本 | 核心设计 | 比较目的 |
| --- | --- | --- |
| C0 | CPU 小图三元组穷举 | 独立正确性依据 |
| C1 | CPU 定向邻接表交集 | 中型图核验及单独 CPU 参考 |
| G0 | 一线程处理一条边 二分求交 | 自行实现的 GPU 基础版 |
| G1 | 一 warp 处理一条边 二分求交 | 固定协作粒度对照 |
| G2 | 按任务规模分成线程和 warp 两类 | 主要优化版 |
| G3 | 按长度比例选择二分或归并 | 有余力再做的扩展 |

G0 中线程遍历短邻接表，在长表中逐个查找，生成每边计数。优先采用每边或每任务局部结果加统一归约，避免每找到一个三角形就更新全局计数。各版本尽量采用相同归约方案，并将其耗时计入比较。

G1 中，一个完整 warp 的 32 个线程按 lane、lane+32 等位置分担短表元素。线程局部求和后使用正确的 warp 归约生成每边结果。所有参与线程必须遵守同步掩码要求；空任务、尾部任务和提前退出不能破坏协作。CUDA warp 原语的参与规则按官方文档实现 [2]。

G2 先跳过空交集任务，再用短表长度或 w 与阈值比较，生成互斥的任务队列，分别启动线程和 warp 内核。每条有效边恰好进入一个队列。第一版可在 CPU 分类，明确记录 O(|E|) 分类及任务列表传输成本；GPU 分类属于后续扩展。

主线先固定二分交集算法，只改变并行粒度。待 G2 稳定后再考虑 G3，避免同时修改算法和调度而无法解释收益。超大任务使用整个线程块、位图和哈希不纳入首轮必做范围。

## 四 数据集与正确性验证

小图验证使用独立穷举，不只比较采用相同交集逻辑的 CPU 与 GPU。检查全部版本输出的 64 位总数，必要时输出每边计数定位差异。

| 验证类型 | 案例与预期 |
| --- | --- |
| 基本图 | 空图 单边 三顶点路径均为 0 K3 为 1 K5 为 10 |
| 特殊结构 | 星形图与完全二部图为 0 不相交 K3 加 K4 为 5 |
| 输入清洗 | 反向边 重复边 自环 非连续编号 孤立顶点 |
| 并行边界 | 任务数为 0 1 31 32 33 及非整块任务 归约尾部 |
| 随机核验 | n=20 不同边概率 多个固定种子 与三元组穷举一致 |
| 不变性 | 打乱输入顺序或重编号后 三角形总数保持不变 |

真实图先使用 SNAP 的 com-Amazon、roadNet-CA、web-Google [3–5]。Amazon 公开规模为 334863 顶点、925872 无向边；道路图体现低度稀疏结构；Google 原始数据为有向网页图，需要按统一规则转换。下载文件 SHA256、清洗后实际顶点数和边数、版本与转换规则写入清单。公开页面计数只作辅助，必须确认图语义相同后才能比较。

合成图包括团链、二维四邻接网格、共享枢纽，以及可调度数分布的随机图。沿用课程团链示例时，512 个 K32 通过不产生新三角形的桥边连接，总数为 2539520。65536 组 K4 共享一个全连接枢纽时，总数为 655360。

共享枢纽在度数定向后可能不再形成高成本交集，不能仅用原始最大度数证明负载不均衡。每张图都统计定向后短表长度、w 的分位数和各任务桶占比，用于解释结果。

为减少阈值选择偏差，先用独立合成校准图或保留的开发图确定阈值，再在主测试图上冻结。主图逐阈值扫描单列为敏感性实验，不把每图事后最优值当作无需调参的实际性能。

## 五 性能实验与统计方法

主要比较为同一块 GPU 上的 G0 G1 G2。C1 的 CPU 时间单独报告；相对 CPU 的速度差不替代 GPU 优化收益。外部 WeTriC 可作为选做对照，记录固定提交、编译配置、图格式和运行范围 [6]。

| 实验 | 控制变量与输出 |
| --- | --- |
| 主比较 | 固定图和归约方案 比较 G0 G1 G2 耗时与加速比 |
| 消融 | 线程固定 warp 固定 分级队列 分级排序分别比较 |
| 阈值 | 在预设候选范围扫描 观察性能和分桶比例 |
| 图结构 | 对照定向后工作量分布与各版本性能 |
| 完整成本 | 分开记录预处理 分类 传输 内核 归约及端到端时间 |
| 重复使用 | R=1 10 100 下比较一次准备后的累计成本 |

计时口径预先固定。T_kernel 使用 CUDA events 覆盖计数内核；T_gpu 覆盖必要的输出初始化、所有计数内核及归约。T_e2e 用主机单调时钟覆盖内存中的原始边表到主机得到计数，包括清洗、定向、CSR、分类、分配和传输；文件读取和解压另列，额外给出包含它们的 T_full。异步 GPU 操作在主机计时终点前完成同步。

重复使用场景写为 T_total(R)=T_prepare+Σ T_execute,r。不同版本准备策略和缓冲复用范围逐项列出，R=1 与重复场景均报告。不要把文件读取混入某一版本而从另一版本中排除。

初步协议为每个配置预热 5 次，正式测量 30 次；预热分配和缓存策略对各版本一致。交错或随机化版本顺序，保存每次结果，报告中位数与四分位区间。很短内核可批量重复计时后除以次数，说明采用热缓存场景。端到端每次重建所需状态，不能把一次预处理平均到单次执行。

除总计数外，记录 GPU 型号、显存、驱动、nvcc、编译参数、block 大小、阈值、输入哈希、提交 SHA 和运行编号。固定电源状态和后台负载；超时、OOM、失败及无加速如实记录。

论文图表计划包括图数据统计、正确性结果、GPU 耗时与加速比、准备及执行时间分解、阈值敏感性、定向后任务分布、重复次数的摊销曲线。所有结果图从原始记录脚本生成。

## 六 硬件资源与开发环境

第一阶段计划使用已有 RTX 4060 8GB 和 32GB 主机内存。正式确认具体桌面或笔记本型号、驱动和 CUDA Toolkit；不根据其他机器的环境记录假定本机已配置完成。核心实现用 C++ 与 CUDA，Python 负责生成小图、独立验证、记录整理与绘图。项目不依赖模型训练或深度学习框架。

32 位邻居编号与 64 位偏移的对称 CSR 约为 8m+8(n+1) 字节，单份向前 CSR 约为 4m+8(n+1) 字节。若另外保存 32 位边端点、64 位每边计数和 64 位任务编号，还会增加约 24m 字节，分类临时区及库缓冲另计。必须以实际布局估算峰值。

以 m=500 万、n=100 万的假设图为例，向前 CSR 约 28 MB，边任务和结果等约 120 MB；这只是已列数组约 148 MB 的估算，不能当成完整峰值。输入解析、排序副本、对称图和 Python 对象可能显著增加主机内存。原始图规模需以转换后结果为准。

课程给出的几百万边规模适合作为 8GB 显存上的首轮目标，先实测峰值再增加规模。超显存分块不纳入首轮范围。开发期优先本机，满足 CUDA 编译运行条件即可，不必先租服务器。

触发租用的条件为本机环境不便配置、长时间实验受共享桌面负载影响、希望增加更大图或第二种 GPU 验证。租用时优先单 GPU、足够的主机内存和稳定可独占时段。4090 或 A800 可作为第二平台，但跨设备时间只说明可迁移性，不能替代同一设备的版本对比。不预设租金和运行小时，待首轮测量后估算。

开发步骤为确认 nvidia-smi 与 nvcc、编译最小 CUDA 程序、完成 CPU 参考、实现 G0、实现 G1 与 G2，再固定工具链版本。Windows 可使用合适的本地 CUDA 编译环境或 WSL2 Linux 环境；具体安装版本根据实机核验。

## 七 进度安排与风险处理

采用四周相对计划，实际日期按课程截止时间调整。正确性优先于扩大规模，先得到完整实验闭环再增加方法复杂度。

| 时间 | 工作 | 验收物 |
| --- | --- | --- |
| 第 1 周 | 阅读定义与相关工作 确认环境 清洗定向 CPU 参考 实现 G0 | 验证集通过 GPU 基础版可运行 |
| 第 2 周 | 实现 G1 G2 检查队列覆盖和 warp 协作 完成初步校准 | 所有版本总数相同 阈值策略冻结 |
| 第 3 周 | 真实图与合成图完整实验 消融 计时分解 资源记录 | 原始 CSV 元数据 重绘脚本 |
| 第 4 周 | 分析适用范围 撰写论文 整理代码和复现说明 | 论文初稿 定稿图表 可复现实验包 |

若 G2 没有加速，先检查定向后是否仍存在足够大的任务、分类是否过重以及 G1 是否本就不占优。缩小适用范围或报告负结果；不能通过只保留有利图、漏记预处理或改动计数定义制造收益。

若分桶开销占主导，比较仅按短表长度分类、一次分类重复使用，以及不分类的固定粒度方案。若某类任务占比过小，减少内核启动或保留 G0。阈值迁移不稳定时，明确设备依赖，并将低成本校准作为扩展研究。

若真实图 GPU 计时过短，增加重复次数或图规模，同时保留热缓存和单次完整流程的区别。若 CUDA 调试进度落后，保证 G0 正确，优先完成一种 warp 优化，停止位图、哈希或整个线程块扩展。

最小可交付范围是 G0 与一种改进版、独立正确性核验、真实图和合成图比较及完整计时分析。推荐范围是 G0 G1 G2、阈值敏感性和摊销实验。第二 GPU、外部高性能实现和 G3 均为选做。
